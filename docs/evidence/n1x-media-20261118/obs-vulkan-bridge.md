# OBS camera recording through Vulkan Video H.264

On 18 November 2026, the installed `p16-media-tools 0.1.0-7` command
`p16-record-obs-vulkan` recorded the P16's internal 1280×720/30 MJPEG RGB
camera from OBS Studio 32.2.2-1. OBS Custom Output (FFmpeg) sent a local NUT
stream with raw NV12 video and PCM s16le audio to the bridge's private FIFO.
Distribution FFmpeg 9.0.2-2 uploaded video frames to the RTX Spark N1X Vulkan
device and used `h264_vulkan`; its AAC encoder handled the audio. NVIDIA driver
615.78.08 was loaded. This is an OBS Start/Stop Recording workflow with a
separate FFmpeg encoder process. It uses Vulkan Video, **not NVENC**.

The isolated OBS profile selected Advanced → Custom Output (FFmpeg), output to
URL `/run/user/1000/p16-obs-vulkan/feed.nut`, container `nut`, video encoder
`rawvideo` (codec ID 13), audio encoder `pcm_s16le` (codec ID 65536), and audio
track 1. OBS's scene included the real internal `P16 RGB` V4L2 source. A
temporary 997 Hz WAV source was added through OBS WebSocket to establish that
audio crossed the same output. The bridge was launched before OBS recording:

```sh
p16-record-obs-vulkan /tmp/n1x-obs-vulkan-bridge/recording-installed.mkv
```

OBS WebSocket `StartRecord` and `StopRecord` returned success. At 6.966 seconds,
`GetRecordStatus` reported `outputActive=true` and 288866304 output bytes.
The OBS log reported camera MJPEG at 1280×720 and 209 frames output (210 drawn)
before Stop Recording. FFmpeg's input was raw NV12 1280×720/30 plus PCM
48 kHz stereo; its output identified `h264_vulkan` and AAC, ran at about
real-time speed, and exited 0 at EOF. The bridge removed its FIFO. The
[independent result](obs-vulkan-bridge-installed.json), generated by
[`check-p16-obs-vulkan-bridge.py`](../../../scripts/check-p16-obs-vulkan-bridge.py),
decoded the final Matroska file successfully: 208/208 downscaled camera frame
hashes were distinct, the audio tone estimate was 997 Hz, and the packet end
times differed by 21 ms. The one-frame OBS-versus-file accounting difference
remains visible. The kernel journal for this run had no new NVRM, Xid or IOMMU
line. A separate pre-recording cancellation left no file or FIFO. The
temporary recordings and tone WAV were deleted after verification; no source
pixels or audio samples were retained.
A separate generated video-only NUT input exercised the bridge's optional
audio mapping: the installed command produced 48 independently decoded
320×180 H.264 frames and exited 0 without an audio stream. That synthetic
check does not replace the real OBS camera/A/V result above.

The package archive SHA256 is
`6cb083cebaa6e4ba6ffc3ca55bb1b4518b85572a2c5933bf1c4f2f39be597f26`;
the installed bridge SHA256 is
`8a9fd82f946f1cd6e23bc850984c709e51fd3df7997e9664e81d80df152a8c05`.
`pacman -Qkk p16-media-tools` reported 19 files and none altered. The
installed [usage guide](../../../platform/video/tools/README.md) gives the
one-time OBS configuration.

OBS's direct `h264_vulkan` Custom Output still fails at `avcodec_open2` with
`Invalid argument`: the generic OBS 32.2.2 FFmpeg output does not establish a
Vulkan hardware device and hands the encoder software frames. The bridge uses
FFmpeg's explicit `-init_hw_device`, `-filter_hw_device` and `hwupload` path.
It copies uncompressed frames between processes, so longer runs, memory and
throughput limits, other OBS scenes and post-resume behavior need separate
qualification. This bounded test establishes actual OBS hardware recording
through a Linux media interface; it does not repair OBS's in-process Vulkan
encoder or the independent NVENC session error 21.
